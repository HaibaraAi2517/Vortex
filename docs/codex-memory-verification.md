## 结果检查与耗时

脚本检查实际工具、返回状态、先读版本再写、提交 revision、前后事实快照、历史版本和独立会话 ID。答案的自动检查只做预期关键词出现和旧住所排除，不是语义裁判。本轮采用自动关键词/状态检查，加主代理与独立子代理逐条语义复核：将九个保存的最终回答与原始事件、Python 输出和事实状态核对，未发现与这九个场景目标相冲突的答案。这不是人类审核员评审，没有独立人工标注数据集，也没有外部用户参与。

九轮子进程耗时合计 **143.15 秒**；报告开始到结束约 144.94 秒，还包含状态读取和记录。Codex 单轮为 15.65–27.89 秒，Python 为 1.74–2.83 秒。这包含进程启动、客户端上下文和模型响应，不是 Vortex 存储延迟，也不能用于不同模型之间的性能比较。

CLI 累计上报输入 token 309,801，其中缓存输入 201,856；输出 token 1,684。这里包含客户端上下文及多次工具交互，且来自配置的 provider，未据此估算费用或宣称成本优势。

同轮完整 Python 测试确认 **62/62 通过**，包含真实 MCP stdio 协议测试。单元/协议测试与上述真实模型场景是两类证据，不能互相替代。

## 首次失败与修复

首次运行在写入阶段收到 `MCP tool call requires approval, but approval policy is never`。两次保存都被客户端拒绝，REST 核对没有事实写入；模型也明确报告尚未保存。失败报告和事件保留在 `target/codex-memory-live.json` 及对应 evidence 目录。

随后仅为隔离验收的 Vortex `remember`、`retract_memory` 设置单工具审批，保持文件沙箱和其他工具限制，并用新的随机 namespace 重新执行全部九轮。普通交互模式继续保留宿主审批；没有开启全局自动批准或授权永久删除。这也是普通非交互 `--message` 可能无法写入的原因，复现时应使用指南里的专用试用空间与 `--isolate`。

## 范围与复现

- 本次运行的是实际 **Codex CLI**，没有验证 Codex 桌面 UI 的全局 MCP 注册、Claude Code 或豆包客户端。
- 成功以示例项目政策启用为前提。MCP 不监听全部聊天，也不能保证没有这些规则时模型仍会主动保存。
- Codex 本次全部按已知 key 使用 `get_memory`，**未调用 `recall`**，所以不是 Codex 语义检索质量验收。
- 第 6 轮包含用户明确的排除说明，只证明这个带限定的归属/计划案例，不能证明未提示情况下的普遍泛化能力。
- 本次没有制造实际并发 409、网络超时或硬删除；对应单元测试或其他 smoke 结果不能计入这九轮覆盖范围。
- 九轮脚本只覆盖两个事实字段，没有多用户身份、长期使用、对抗输入、服务重启或规模压测结论。也没有无记忆/共享 Markdown 对照或 LongMemEval 答案质量比较。
