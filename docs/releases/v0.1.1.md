# Vortex v0.1.1 Release Notes

Released: 2026-08-01

`v0.1.1` is a stable patch release that aligns the public recall behavior with
the accepted retrieval decision and tightens the interviewer-facing review path.
The `v0.1.0` tag remains unchanged.

## What Changed

- `RecallQuery` now defaults to `VECTOR_ONLY` with
  `rerankEnabled=false`, matching the case-isolated LongMemEval decision.
  Explicitly enabling reranking without selecting a type retains linear score
  fusion for compatibility.
- Hybrid and reranker benchmark paths now declare their modes explicitly, so
  evaluation semantics no longer depend on public DTO defaults.
- The English and Chinese READMEs distinguish the default path from optional
  Hybrid, linear-fusion, and gated Cross-Encoder paths.
- Quickstart prerequisites now include the real PowerShell/Bash tool
  requirements.
- Each core engineering decision links directly to implementation classes.
- Repeated status, evidence, repository-map, and tech-stack sections were
  removed to shorten the interviewer review path.
- Demo copy now describes an interviewer-ready architecture review instead of a
  GitHub popularity goal.

## Compatibility Note

Clients that relied on the unintended `HYBRID + LINEAR_SCORE_FUSION` implicit
path should now send `retrievalMode` and `rerankEnabled` explicitly, plus
`rerankerType` when selecting a non-linear implementation. Explicit Hybrid
and reranker requests remain supported.

## Known Boundaries

- No production-grade auth, RBAC, tenant isolation, rate limiting, or audit log.
- No distributed consensus, multi-node scheduling, or cross-region replication.
- Main-path latency excludes external LLM generation.
- LongMemEval Recall@5 measures oracle-fragment retrieval, not final-answer
  accuracy.
