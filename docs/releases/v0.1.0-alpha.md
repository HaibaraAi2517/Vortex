# Vortex v0.1.0-alpha Release Notes

Vortex v0.1.0-alpha is the first public-ready alpha for the project's memory,
hybrid retrieval, and runtime recovery kernel for long-running AI agents.

This release is intended for local evaluation, integration experiments, and
code review. It is not positioned as a production SaaS or a drop-in hosted
agent platform.

## Highlights

- Long-term memory APIs for storing, recalling, pinning, evicting, and giving
  feedback on memory fragments.
- Hybrid retrieval with namespace/tag filters, keyword and vector candidates,
  reranking, and token-budgeted context assembly.
- Three-tier memory storage using Caffeine for hot cache, Milvus for vector
  search, and MinIO for cold object persistence.
- Task-state APIs for DAG mutation, checkpoint creation, WAL-backed recovery,
  branch/switch/merge, and Graphviz export.
- A container-first quickstart stack with Vortex, Milvus, MinIO, Redis, and
  etcd.
- A no-key quickstart agent demo that shows memory off/on behavior and recovery
  from a killed worker process.
- No-key Java integration examples for Spring AI `ChatClient` advisors and
  LangChain4j `AiServices` request transformers.

## Quick Start

Start the quickstart stack:

```powershell
docker compose -f docker-compose.quickstart.yml up --build -d
```

Check health:

```powershell
Invoke-RestMethod -Uri 'http://localhost:8080/actuator/health' -Method Get
```

Run the no-key agent demo:

```powershell
.\examples\quickstart-agent\run.ps1
```

More details are in [docs/quickstart.md](../quickstart.md) and
[examples/quickstart-agent/README.md](../../examples/quickstart-agent/README.md).

## Benchmark Evidence

These are deterministic benchmark results from committed evidence runbooks, not
production guarantees.

| Area | Evidence-backed result |
| --- | --- |
| Hybrid recall | `Hybrid+Rerank` improved Recall@5 from `0.7917` to `0.9500` versus `Vector+Rerank`, a `+20.00%` relative lift, with `0/100` run errors across five retrieval modes. |
| Main-path latency | Moving memory extraction, summary, embedding, L1 admission, L2 indexing, and L3 archival off the request path reduced measured P99 from `1172.50 ms` to `220.34 ms`; average latency moved from `829.40 ms` to `186.64 ms`. |
| Runtime recovery | The deterministic fault-injection matrix passed `32/32` covered cases across service restart, tool failure, LLM exception, state integrity, and concurrency categories. |

See [docs/benchmark.md](../benchmark.md) for source links, scope, boundaries,
and reproduction notes.

## Known Limits

- Alpha-stage APIs may still change.
- Authentication, RBAC, tenant isolation, rate limits, and audit logs are not
  implemented as production features.
- Benchmarks do not include real external LLM generation in the measured
  main-path latency.
- Runtime recovery evidence covers deterministic cases in the current
  checkpoint/WAL/runtime-state surface; it is not a complete production
  recovery claim.
- Public LongMemEval or other public-dataset metrics are not promoted in this
  release.
- Distributed consensus, multi-node scheduling, and cross-region replication
  are not claimed.

## Upgrade Notes

This is the first alpha release note, so there is no prior public release to
upgrade from. For local experiments, start from the quickstart stack and keep
Milvus collection changes isolated with a dedicated collection name or prefix.
