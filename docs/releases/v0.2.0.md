# Vortex v0.2.0 Release Notes

Release date: 2026-08-21

`v0.2.0` is the first Vortex release packaged for direct REST-service adoption.
It adds a versioned OCI image and executable JAR release path while tightening
the memory, recovery, security, and operational contracts introduced after
`v0.1.1`.

## Highlights

- Recall ranking v2 adds hybrid keyword/vector candidate fusion with reciprocal
  rank fusion, explicit MMR and scoring policies, exact-query signals, and
  feedback/access-frequency inputs. The additional Cross-Encoder remains gated
  and disabled by default.
- Memory admission and reclaim now have bounded concurrency, namespace quota
  enforcement, stronger pin/persistence coordination, and expanded SLO and
  contention evidence.
- The REST boundary adds Bearer-token authentication, namespace authorization,
  request-size and rate limits, redacted failures, and structured audit events.
- Execution ID replay supports Redis-backed durable state and preserves
  uncertain `IN_PROGRESS` outcomes instead of silently repeating side effects.
- Quickstart persists WAL, DLQ, processed keys, and application state under a
  non-root-owned volume. The semantic page table uses a versioned v2 key so an
  older release does not deserialize newer derived cache state during rollback.

## Distribution

- OCI image: `ghcr.io/haibaraai2517/vortex:0.2.0`
- Executable application JAR: `vortex-app-0.2.0.jar`
- Java CycloneDX SBOM and image SPDX SBOM
- SHA-256 checksums, release manifest, Apache-2.0 license, and third-party notices
- Keyless Cosign signature on the immutable image digest

Java artifacts are not published to Maven Central or GitHub Packages in this
release. Use the OCI image for the supported external REST-service path; build
from source when embedding Vortex modules in another JVM application.

## Validation

The release candidate passed:

- clean Maven verification and distribution assembly;
- `13/13` isolated Docker integration cases;
- Windows, Linux, and macOS Quickstart flows;
- anonymous Swagger/OpenAPI loading with authenticated business APIs and metrics;
- container-replacement replay and Redis Execution ID replay;
- cold-volume backup/restore and recalled-data verification;
- `v0.1.1 -> v0.2.0 -> v0.1.1` upgrade/rollback rehearsal;
- official Milvus Backup v0.5.16 logical backup/restore;
- signed candidate-image pull and digest-based Quickstart on a fresh runner.

The formal tag workflow repeats clean verification and integration tests, builds
the immutable image, signs it by digest, smoke-tests the pulled image, and only
then publishes the GitHub Release assets.

## Compatibility And Boundaries

- This is a minor release because security boundaries, persistence semantics,
  default recall behavior, and distribution contracts changed.
- Quickstart migration repairs existing application-volume ownership before the
  non-root Vortex container starts.
- The semantic page table is rebuildable derived state. The v2 key intentionally
  leaves the older key untouched for rollback compatibility.
- The supported external path is a trusted isolated network using the supplied
  token, namespace allowlist, rate limits, audit events, and loopback port.
- This release does not claim production OIDC/mTLS, fine-grained multi-tenant
  RBAC, distributed consensus, cross-region replication, or public-Internet
  deployment readiness.
