# Vortex Memory Recall 打分方案

## 1. 当前结论

生产默认路径已晋级为：

- Retrieval：`HYBRID`
- Ranking：`RRF`
- Reranker：`NONE`

Recall Ranking V2 已通过 120-case dev 和独立 120-case sealed validation 门禁。
没有精确特征时，它保持 VectorOnly 的候选边界和 Legacy 稳定排序；只有冻结的精确
特征才打开词法候选与 RRF。

`HYBRID_RRF_MMR` 保留为实验策略。当前证据显示它会改变个别结果顺序，但没有带来
Recall、MRR 或 NDCG 收益，因此不参与默认路径晋级。

## 2. 设计原则

1. 召回相关性、缓存保留价值和结果多样性必须分开建模。
2. 没有独立词法证据时，V2 必须返回已经验证过的 Legacy 稳定排序，不允许退化成新的纯 Dense 排序。
3. Memory Prior 最多占总分 10%，不能覆盖问题相关性。
4. 只有高置信精确特征才能打开词法分支，普通数字和普通连字符词不得触发。
5. 排序对比必须使用只读评测路径，任何 L1 admission、持久化、importance 强化、访问频率、paging、学习 session 或 SLO 写入都会污染 ablation。
6. dev 用于选择和冻结配置；validation 只允许在冻结后运行一次；reserve 保持未触碰。

## 3. 候选生成

### 3.1 向量候选

始终使用当前 BGE-Small + Milvus Vector 候选路径。候选池、标签过滤、token budget 和
namespace 隔离规则保持不变。

### 3.2 词法候选

只有 `ExactQueryFeatureDetector` 返回高置信信号时才启用：

| 信号 | RRF 词法权重 | 示例 |
| --- | ---: | --- |
| Email | 0.15 | `owner@example.com` |
| 命令或参数 | 0.15 | `--force`、反引号命令 |
| 路径或文件名 | 0.15 | `C:\\work\\a.json`、`config.yml` |
| UUID 或技术 ID | 0.15 | `VTX-42`、`job_id:abc` |
| 结构化日期或版本 | 0.08 | `7/22`、`v2.1` |
| 普通数字、金额、普通连字符词 | 0 | `$12`、`well-known` |

诊断必须记录：

- `keywordFusionWeight`
- `keywordTriggerReason`

## 4. 排序

### 4.1 无词法信号

当 `keywordFusionWeight = 0` 时，`HYBRID_RRF` 必须直接返回 Legacy active profile
排序锚点。它与 `VECTOR_ONLY` 的逐 case 返回顺序必须完全一致。

### 4.2 有词法信号

语义与词法排序使用 RRF 融合，禁止直接相加原始分数：

```text
rrfScore =
  1.00 / (60 + vectorRank)
+ keywordWeight / (60 + keywordRank)
```

融合分数按理论最大值归一化到 `[0,1]`。相同分数保持原候选顺序。

### 4.3 Memory Prior

仅在词法分支实际启用并进入 V2 排序时应用：

```text
utilityPrior =
  0.50 * importance
+ 0.30 * freshness
+ 0.20 * decayedRecallFrequency

finalScore =
  0.90 * relevance
+ 0.10 * utilityPrior
```

召回频率使用 7 天半衰期的衰减计数；它不能写回 Fragment schema。评测每次运行前清空
对应 fragment 的 recall-only 信号。

## 5. MMR

MMR 只在显式 `RRF_MMR` 策略下执行：

- 候选窗口：`TopK * 2`
- 相关性权重：0.85
- 多样性惩罚：0.15
- 只惩罚相似度大于 0.95 的近重复候选

MMR 必须以独立质量收益证明其价值。仅改变顺序、但 Recall/MRR/NDCG 不提升时，不得晋级。

## 6. 淘汰策略

召回评分不得调用 `MemoryFragment.describeEvictionScore()`。淘汰继续使用独立目标：

```text
retentionDensity = predictedFutureUse / tokenCount
```

Recency、Importance、访问频率、Token 成本和 Pin 属于保留价值，不属于答案相关性。
Pin 继续作为硬约束。

对于知识更新，后续应引入 `validFrom`、`validTo` 和
`supersedesFragmentId`，不能只依赖 Recency 推断当前事实。

## 7. 评测协议

冻结设置：

- 数据：LongMemEval case-isolated split
- TopK：5
- Token budget：4096
- Generation、scheduler、paging：关闭
- 本地 BGE-Small
- 每次运行使用独立 Milvus collection、MinIO prefix、WAL、DLQ 和 processed-key 文件
- 初始 fragment 同步写入 L2/L3
- 所有排序模式通过 `recallReadOnlyForEvaluation()` 执行
- dev 比较：`VECTOR_ONLY,HYBRID_RRF,HYBRID_RRF_MMR`
- validation 比较：`VECTOR_ONLY,HYBRID_RRF`

只读评测禁止：

- L2 命中回灌 L1
- recall-reinforcement 持久化
- importance 或 last-access 强化
- decayed recall frequency 写入
- page fault / prefetch
- adaptive-learning recall session
- 运行时 SLO 指标写入

## 8. 晋级门禁

以下阈值在查看 validation 结果前冻结，validation 后不得放宽。

| 门禁 | 要求 |
| --- | --- |
| 完整性 | 分区全部 case 完成，errors = 0 |
| Recall@5 | 候选不得低于 VectorOnly |
| MRR | 候选不得低于 VectorOnly |
| NDCG@5 | 候选不得低于 VectorOnly |
| case-level Recall | wins >= losses，且 losses = 0 |
| case-level NDCG | wins >= losses |
| 无词法不变量 | `keywordFusionWeight=0` 时改序数必须为 0 |
| 触发边界 | 只允许冻结的精确特征类型，普通数字不得触发 |
| P95 | 增量 <= 10 ms 且相对增量 <= 5% |
| P99 | 增量 <= 20 ms 且相对增量 <= 5%，绝对值 <= 500 ms |
| MMR | 必须有独立质量收益，否则不晋级 |

流程：

1. dev 通过后冻结唯一候选、代码产物、模型、数据 hash 和门禁。
2. sealed validation 只运行一次，不再调权重。
3. validation 全部门禁通过后，将默认 retrieval/ranking 切换为 `HYBRID + RRF`。
4. validation 任一门禁失败，默认路径保持 `VECTOR_ONLY + LEGACY`。
5. reserve 不用于本轮选择、调参或补考。

## 10. 回滚条件

默认路径未来即使切换到 RRF，出现以下任一情况也应立即回滚到
`VECTOR_ONLY + LEGACY`：

- Recall@5、MRR 或 NDCG 相对基线下降
- 非精确查询出现词法触发
- P95/P99 超过冻结门禁
- 无词法查询与 Legacy 排序不一致
- 出现跨 namespace 返回、评测状态污染或持久化错误
- 线上反馈显示精确特征规则产生系统性误触发
